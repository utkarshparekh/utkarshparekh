Explicit bounds checks for AST column references

MERGED · PR #23021

A focused correctness fix: reject an out-of-range AST column index with a clear bounds error before accessing the table column.

01 / THE PROBLEM

Invalid references reached table access

column_reference::get_data_type() obtained a column type from a table view using the expression's column index. An invalid index did not have an explicit, domain-specific check at that point.

02 / WHY IT MATTERS

Fail clearly at the validation boundary

Checking the index where it is used makes invalid references fail predictably and gives callers a clear std::out_of_range error, rather than relying on a lower-level vector range-check message.

03 / MY CONTRIBUTION

Validate both table-reference paths

The merged change adds explicit index validation for the single-table and left/right-table overloads of get_data_type(), and adds a regression test covering an index beyond the available columns.

04 / IMPLEMENTATION

Check bounds before reading the column type

Both overloads check that the index is non-negative and less than the selected table's column count, then retrieve the type. The test verifies that an out-of-range reference throws std::out_of_range.

CUDF_EXPECTS(index >= 0 && index < table.num_columns(),
"column index out of range",
std::out_of_range);

This is a simplified illustration; see the linked source for the exact implementation.

05 / ENGINEERING TRADEOFFS

Small check, explicit error contract

The change adds validation to the type lookup paths and uses the project's expectation mechanism to report an out-of-range error. The PR adds a focused regression test; no performance claim is made here.
